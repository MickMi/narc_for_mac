# NARC Project Profile

## Goal

让重度终端与 AI 工作流用户通过一个常驻 macOS 桌面的个人助手入口，快速捕获信息、感知关键状态、找回上下文并执行高频动作，而不必反复切换应用和重建注意力。

## Audience

- 同时使用 Claude Code、Codex、终端、IDE 和多个沟通工具的个人开发者。
- 需要随手记录 Todo、Note、想法和上下文，并希望稍后可靠找回的人。
- 经常在多个窗口、显示器和 Space 之间切换，希望减少重复操作的人。

## Current Product Promise

v2 开发预览围绕四个连续动作提供本地能力：

1. **Capture**：通过 Inbox 先记下内容，再显式整理为 Todo 或 Note；没有可处理 Todo 时输入区自然成为首要动作。对于另一个 App 中已经选中的文字，可由用户按快捷键直接创建本地 Todo，不要求 AI 分类。
2. **Recall**：从本地 Todo、Notes 和已标记窗口中找回与当前任务相关的上下文；有可处理 Todo 时，面板优先呈现一项“下一件事”。
3. **Monitor**：低干扰地呈现应用级未读、Todo 数量与可找回窗口，不持续或自动读取消息正文，也不承诺会话级状态。
4. **Act**：从主面板或非激活提醒卡完成、延期待办，打开记录，激活或排列窗口；对需要系统权限的动作先解释再请求。

AI 会话检索、后台任务监控与受控工具调用属于 v2.1 及之后的长期方向，不是当前版本承诺。

## Product Boundary

- NARC 是个人助手和系统能力入口，不替代终端、IDE、笔记软件或任务管理平台的全部能力。
- Workspace 已从主产品的用户入口软下线；嵌入式终端与 Dashboard 底层代码仅保留一个版本用于回滚，不再作为产品承诺或默认模块。
- Todo 与 Notes 第一阶段采用本地优先存储，不包含团队协作、云同步、复杂项目管理或富文本数据库。
- 第一阶段的“插件化”指编译期内置模块契约；不加载第三方动态 Swift 代码，不开放未受控脚本执行。
- AI 助手最终可以跨模块查询和执行动作，但模型提供商、费用、隐私与外部写入权限必须在后续版本单独确认。
- 删除数据、向外部系统发送内容、执行脚本等高风险动作必须获得明确授权；低风险本地动作需要可撤销或有清晰反馈。

## v2.0.0 · 2026-09-14 · Inbox 焦点与主动 Todo 提醒

- Inbox 使用状态驱动的信息层级：存在可处理 Todo 时，“下一件事”位于输入区之前并成为唯一主视觉；没有可处理 Todo 时，输入区自然回到第一位。
- 待整理 Inbox 默认折叠为数量摘要，用户主动展开后再转换或删除；主面板不再同时堆叠常驻功能说明、完整历史和重复快捷键提示。
- 悬浮 `N` 左下角用蓝色数字显示可处理 Todo 数量，并继续与右上角应用级未读 Badge 保持两条独立语义；数量提示不包含任务正文。
- 除用户主动打开的主面板外，悬浮球旁可以按固定节流显示一张独立非激活提醒卡。卡片一次只呈现一项 Todo，提供“完成”“1 小时后”“收起”，不打开主面板、不激活 NARC、不抢键盘焦点。
- 首版节奏固定为启动暖机 30 秒、Todo 变化后静默 15 分钟、单次展示 15 秒、展示后冷却 2 小时、每日最多 3 次；暂不增加频率设置，先通过真实使用确认提示强度。
- 提醒继续复用唯一的本地 `AssistantStore`；完成和延期写入现有本地数据，节流账本只记录日期、次数和下次允许时间，不保存 Todo 正文或任务 UUID。
- 这项能力不连接 AI、账号或网络，不新增系统权限，不使用 macOS 系统通知或声音。当前状态是可体验预览，需在用户确认信息层级与提醒强度后再进入正式验收。

## v2.0.0 · 2026-09-11 · 显式划词捕获

- 用户在其他 App 中主动选中文字后，按默认 `⌃⌥T` 直接创建本地 Todo；这是 Capture 的显式入口，不属于 Monitor，也不改变 Return 默认进入 Inbox 的主路径。
- 快捷键触发时先锁定前台 App 与焦点控件，再立即尝试一次公开标准 Accessibility 选区读取；不持续监听、不读取或改写剪贴板、不模拟 `⌘C`、不使用 OCR、AI、私有 API 或外部服务。
- 不超过 240 个字符且不超过 3 个非空行时直接保存；其余不超过 65,536 个 UTF-16 文本单元的正常选区先确认。取消不写入；确认使用读取完成后的同一快照，不因确认窗口带来的焦点变化重新读取。超过上限明确拒绝并要求缩小选区。
- 成功反馈不显示正文，并允许用本次创建的精确 UUID 撤销；空选区、不兼容、受保护内容、暂时失败、权限缺失和写盘失败均不得伪装为成功。
- 15 项全局动作统一使用显式快捷键配置：窗口布局、Pin、悬浮球召回、快速记录和划词 Todo 均可从偏好设置选择至少两个修饰键与受支持的主键；布局还可单独停用。新组合冲突或注册失败时，继续使用并展示原来实际生效的组合，不影响其他全局快捷键。
- 这项能力复用窗口工具已有的辅助功能权限，不新增屏幕录制等权限。手动 Todo 与随手记保持无权限可用；划词、窗口排列和窗口标记需要辅助功能权限。
- 兼容性结论以[App × 具体界面矩阵](research/selected-text-todo-compatibility.md)为准；TextEdit、Safari/Chrome、VS Code、Preview 与企微的真实 App 行目前仍待验证，不能把网页正文、输入框、PDF 文本层、扫描件或消息区合并判断。
- 本阶段不改变 GitHub source-only 路线，不增加 DMG、PKG、预编译 App、Developer ID、公证或自动更新。

## v2.0.0 · 2026-09-08 · 本地 Todo 注意力闭环

- 本阶段建立的完成、延期和候选排序仍是当前基础；其中“匿名、非数字 cue”和“只在用户打开面板后呈现”的初版表达，已由上方 2026-09-14 阶段修订。
- Todo 的基础价值不依赖 AI：普通 Return 保持 Inbox 心智，`⌘Return` / Todo 按钮只在用户明确时直接建任务。
- 悬浮 `N` 是注意力提示而不是任务列表。有可处理任务时显示独立蓝色数量 cue；右上角应用未读 Badge 保持原语义，任务正文不会出现在球面。
- 用户主动打开面板后可处理一张“下一件事”卡片；固定节流也可以在悬浮球旁显示独立提醒卡。两者都不以系统通知或声音打断工作，主动卡不会激活 NARC 或抢焦点。
- 延期写入本地数据并在到期后重新进入候选；“下一项”只属于当前面板，不把浏览偏好写进任务文件。
- 当前版本不加入截止日期、优先级、重复任务、自然语言理解或外部同步。它先证明“看见—选择—处理—回来”的低干扰闭环。

## v2.0.0 · 2026-09-07 · 双入口与注意力召回

这是当前有效的产品定义；与下方历史阶段冲突时，以本阶段为准。

- 顶部菜单栏负责稳定找回与持续状态，桌面悬浮 `N` 负责当前屏幕上的注意力锚点；默认不显示 Dock。
- `⌃⌥N` 是幂等召回动作：悬浮球移动到鼠标所在屏幕并保持面板展开，不作为关闭开关。
- 捕获统一进入 Inbox；面板、全局 Quick Capture 与 Assistant 复用同一草稿，再由用户转 Todo 或 Note。
- 应用未读只使用可验证的 macOS 应用级 Badge；多实例取最大值，读取失败显示未知，不读取消息正文或会话级状态。
- 引导在 Inbox 入口内完成；只有第一条记录写盘成功才完成核心引导。
- 启动不主动索取辅助功能或通知权限；权限请求由用户首次使用对应动作触发。
- Workspace 不恢复，AI、外部连接器和动态插件继续留在后续版本。
- 分发保持 source-only；本机 `.app` 只是运行载体，不增加安装包、发行证书或公证链。为让辅助功能授权跨源码更新保持身份连续，普通安装自动复用每用户、每台 Mac 的本地钥匙串身份。

## v2.0.0 · 2026-09-07 · 权限连续性与本地身份

- 保留全部窗口找回与排列能力，不以规避权限问题为由砍掉 Accessibility 路径。
- 目标位置已有严格有效的 NARC、对应本地私钥仍可用且身份属于允许范围时，普通安装自动继承该 signer；只有干净新用户才创建 `NARC Local Code Signing Identity v1`。指纹标记与已安装 App 冲突、身份丢失、重复或不可用时失败关闭，不得静默换证书或回退到 ad-hoc。
- 本地身份不是 Developer ID 或可分发签名：新建 Local v1 时，安装器以不可导出方式导入私钥，并把初始访问范围限制为系统 `codesign`；继承身份不导出或改写其私钥。任何私钥都不进入 Git、构建产物、CI、日志或网络，GitHub 仍只发布源码。
- 为实现后续更新无重复确认，同一用户下的其他进程也可能调用系统 `codesign` 使用该身份；它们不能导出私钥，但本地身份不提供发布者担保。若未来改为每次签名人工确认，必须作为明确的安全/体验变更重新裁决。
- CI 和一次性开发构建必须显式选择 ad-hoc；普通用户不需要手工准备证书或执行签名命令。
- 首次系统信任确认与首次辅助功能授权是两个独立步骤；同一用户、同一 Mac、同一身份下，后续源码更新应复用授权。早期预览若已误从 `NARC Dev` 迁移到 Local v1，只允许通过完整指纹确认的显式恢复事务切回，不操作 TCC。

## v2.0.0 · 2026-08-20 · 个人 AI 助手基础

本阶段最初确认：

- 先在不改变 Workspace 的前提下建立个人助手基础；该假设已被下方“产品收敛”阶段修订。
- 新增统一的个人助手入口，优先解决快速记录 Todo 与 Note 的真实高频需求。
- Todo、Notes、通知和窗口逐步遵循同一套内置模块契约，不要求一次性重写所有旧功能。
- Quick Capture 由用户显式选择 Todo 或 Note，避免在尚未确定模型方案时伪造“AI 自动理解”。
- 外部模型编排、Apple Notes/Reminders、日历、GitHub 和第三方插件属于后续版本，不进入 v2.0 基础范围。

本阶段要证明的不是“功能数量增加”，而是以下闭环成立：用户能在不离开当前工作的情况下快速记录，保存结果来自真实本地状态，并能在 NARC 中重新找到和管理这些记录。

## v2.0.0 · 2026-08-20 · 产品收敛与可靠性修复

本阶段修订并锁定：

- Assistant 成为 Dock 重开、悬浮窗右键和 Panel 的唯一主产品入口；Quick Capture 继续承担最高频捕获。
- Workspace 从 Panel、右键菜单、偏好设置、默认模块和 `⌃⌥W` 中软下线；底层保留一版只为安全回滚，不继续新增功能。
- 应用未读数必须来自可验证的 macOS LaunchServices 状态；同一应用存在多个实例时去重读取，查询失败不能伪装成新的零未读。
- Dock 和桌面悬浮圆点统一使用视觉居中的大写 `N`，消除两套字标与基线偏移。

产品收敛的判断标准不是“删除了多少代码”，而是用户只看见一条清晰主线：快速捕获、查看个人记录、感知真实状态并执行高频动作；保留的 Workspace 底层不再影响这条路径。

## v2.0.0 · 2026-08-20 · GitHub 本地运行与首次使用

本阶段锁定以下交付方式和边界：

- NARC 通过 GitHub 源码分发；用户运行 `bash scripts/install.sh`，脚本在本机准备 App 并放到 `~/Applications/NARC.app`，不要求 App Store、付费开发者账号或 `sudo`。
- 普通用户只需记住两个动作：点击悬浮 `N` 查看状态，按 `⌃⌥Q` 快速记录 Todo/Note；构建、签名和 Bundle 细节不成为日常操作。
- 首次启动先显示简短使用指南，不叠加系统权限提示；完成后不重复弹出，且可从悬浮 `N` 右键菜单重新打开。
- 当时 Accessibility 只用于窗口排列、钉选与相关窗口动作；上方 2026-09-11 阶段已把用户主动触发的划词 Todo 纳入同一权限边界。手动 Assistant、Todo/Note、Quick Capture 和应用级 Dock Badge 仍不以该权限为前置条件。
- 微信重点会话当前只适合做用户显式维护的本地书签。微信 4.1.11 的真实 AX 树没有会话行、selected 或 unread 语义，因此不能承诺会话级未读监听。
- OCR 需要屏幕录制且只能推断可见区域；私有数据库、进程注入和 Hook 不进入产品方案。详细证据见 [微信重点会话可行性研究](research/wechat-priority-conversations.md)。

这一阶段的完成标准是：新用户能从干净源码用一条命令安装，在真实 App 中理解并进入两条核心路径；同时所有微信细粒度能力都以真实状态源为准，未知状态不显示为零。

## v2.0.0 · 2026-08-23 · 源码分发边界收口

> 本阶段关于 ad-hoc 与重复授权的旧判断，已由上方 2026-09-07 的本地身份决策修订；source-only、无安装包和无发行签名的边界保持不变。

- 唯一支持的普通用户交付路径是 README 首屏的一条 GitHub 命令；它完成源码拉取、本机构建、放置和启动。
- 不提供 DMG、PKG、预编译 App ZIP 或 GitHub Release 安装包，不引入 Developer ID、公证或自动更新框架。
- 本地 `.app` 是 macOS 运行载体，不是安装包产品；普通安装的本地身份不作为用户手工步骤或分发签名。
- 手动个人助手与应用级未读不依赖辅助功能权限；划词 Todo 与窗口整理功能遵循 macOS 的明确授权机制，后续源码更新会复用 2026-09-07 决策中锁定的本地身份。

这项收口优先保护获取成本和可维护性：任何重新引入预编译发布物或证书链的提案，都必须先修改版本边界并获得用户明确裁决，不能作为“顺手补齐发布流程”进入实现。
