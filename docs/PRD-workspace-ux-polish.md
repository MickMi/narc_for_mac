# PRD: Workspace 体验打磨（Dashboard 软化 + 智能复制气泡 + 拖拽灰底修复）

## 📌 需求摘要
- 一句话描述：三件独立的体验打磨——把 Dashboard 视觉做圆润优雅、把"智能去缩进"从粘贴侧翻到复制侧并改成选区气泡、修掉拖拽悬浮窗时的方形灰底。
- 类型：① 视觉重构（软化）/ ② 交互重做 / ③ Bug 修复
- 优先级：P1（体验类，非阻塞功能）

## 🎯 目标与边界

### 核心目标
让 Workspace 用起来更顺手、更耐看：Dashboard 不再是"简单圆角"的廉价感；从终端复制 Claude 输出时一键得到无缩进的干净文本；悬浮窗拖拽时视觉干净无穿帮。

### 核心场景（User Story）
1. **智能复制**：我在终端里选中 Claude 打印的一段缩进代码 → 选区旁浮出一个小气泡 → 我点它（或按 ⌘⇧C）→ 粘到别处时公共缩进已被去掉，直接可用。
2. **拖拽干净**：我拖动右下角悬浮窗换位置 → 全程只看到那个圆 + 轻微缩放，**不再有方形灰块**穿帮。
3. **耐看**：我打开 Dashboard → 圆角是连续曲率的柔和感、阴影分层柔和、留白舒展，而不是生硬的直角圆角。

### 明确排除（不做什么）
- ❌ **#2** 智能复制只在 NARC Workspace 内嵌终端生效，不管外部 iTerm/Terminal。
- ❌ **#2** 只做"去公共缩进的纯文本"，不做复制为 Markdown / 富文本 / 带语法高亮。
- ❌ **#2** ⌘C 行为**不改**（保持系统原始复制），不抢占 ⌘C。
- ❌ **#1** 不改 Dashboard 的**布局骨架**（toolbar / HSplitView / 左 tab 右 pane 结构）和任何交互逻辑，只软化视觉。
- ❌ 不引第三方库；声音/材质/动画都用系统能力。
- ❌ 不碰上一轮已完成的状态监控/降噪逻辑。

### 验收标准（可量化）

**#1 Dashboard 软化**
1. 我出 `docs/design/workspace-softening-design-brief.md` 设计简报；Design AI 据此产出 `design-handoff/` 下 SwiftUI，接线后 Dashboard 呈现：连续曲率圆角、柔和分层阴影、更舒展留白、精细分隔线/材质。
2. 软化后所有现有功能无回归（tab 增删改/切换、claude 状态徽标、审批 popover、空状态）。
3. 编译通过。

**#2 智能复制气泡**
4. 在内嵌终端选中**非空**文本时，选区附近浮现一个小气泡；选区清空或终端失焦时气泡消失。
5. 点气泡 **或** 按 ⌘⇧C → 选中文本经 `dedent`（去最小公共前导空格）写入系统剪贴板；⌘C 仍是原始复制。
6. 右上角"智能粘贴"提示条移除；`⌘⇧V` 智能粘贴键绑定移除（`dedent` 工具函数保留复用）。
7. 复制成功有轻量反馈（气泡变"已复制"或一闪即逝）。

**#3 拖拽灰底**
8. 拖拽悬浮窗全过程：屏幕上只有圆形 widget + 既有的缩放/微旋转，**无任何方形灰色底板**；松手后恢复正常，无残影。

## 👤 用户旅程
- **#2**：用户在终端拖选文本 → `NarcTerminalView` 检测到选区变化 → 在选区屏幕矩形上方浮一个 SwiftUI/AppKit 气泡 → 用户点气泡/按 ⌘⇧C → 取选中字符串 → `dedent` → 写剪贴板 → 气泡给"已复制"反馈 → 选区取消/失焦 → 气泡消失。
- **#3**：用户按住 widget 拖动 → `FloatingWidgetWindow` 进入 dragging → `FloatingWidgetView` 当前用 `regularMaterial` + `scaleEffect` + `rotationEffect`，材质矩形底层在变换下穿帮 → 修复后变换不再暴露矩形。
- **#1**：用户开 Dashboard → 看到软化后的视觉。

## ⚙️ 技术约束
- 复用 `NarcTerminalView.dedent(_:)`（现成，算法不变）。
- **#1** 视觉以 `Sources/Design/DesignTokens.swift` 为准，Token 冲突时 Design 拥有定义权（见 DESIGN-COLLABORATION.md）。
- **#2** 用 SwiftTerm 暴露的选区接口（蓝图阶段需核实 `LocalProcessTerminalView`/`TerminalView` 的 selection API 与坐标换算能力）。
- **#3** 仅用 SwiftUI 原生手段（`compositingGroup` / `clipShape` / 拖拽态换纯色之一），不改窗口层级结构。

## ⚠️ 风险与依赖
- **#2 最大风险**：SwiftTerm 是否暴露"选区变化回调"和"选区屏幕矩形"。若不暴露，气泡定位需退化方案（如固定贴在终端右上角，或监听 `NSView` 选区/鼠标抬起）。蓝图阶段必须先验证接口，必要时写进 gaps 回流。
- **#3 风险**：修复手段需实测确认灰底消失且不破坏圆形阴影/缩放观感——三种手段择一，蓝图给首选 + 兜底。
- **#1 依赖**：Design AI 产出需编译验证 + 保持视觉意图；接线遵循"先编译→再接线→功能测试"。
- **影响范围**：#2 触 `TerminalPaneView.swift`、`DashboardView.swift`（移除提示条）；#3 触 `FloatingWidgetView.swift`；#1 触 Dashboard 相关 View（Design AI 产出后接线）。三者互不耦合。

## 📝 攻防记录
- 挑战 1：智能去缩进放粘贴侧还是复制侧？→ 用户确认痛点在**复制侧**（选中 Claude 输出带缩进），翻到复制侧。
- 挑战 2：⌘C 是否抢占？→ 用户明确**不抢 ⌘C**，用气泡 + ⌘⇧C，保留原始复制能力。
- 挑战 3：Dashboard 改多大？→ 用户选**软化**（不动布局骨架），走 Design AI。
- 挑战 4：拖拽灰底要不要问用户？→ 否，纯 bug，直接修。
